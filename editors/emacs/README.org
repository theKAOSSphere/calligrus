#+title: calligrus.el: live Markdown preview for Emacs

Drives =calligrus --editor= (the Calligrus executable) from Emacs: one shared preview window shows whichever Markdown buffer you are in, follows your cursor, updates as you type, highlights what you search for, and Ctrl+click in the preview moves point to that spot in the source. Protocol: spec sections 15, 17 and 23 (JSON lines on Calligrus's stdin; =goto= lines back on its stdout). Plain Emacs Lisp, Emacs 27.1+ (needs native JSON), no dependencies; works with or without Evil, Doom or markdown-mode.

* Install

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/calligrus/editors/emacs")
(require 'calligrus)            ; or (autoload ...) via package-vc / use-package :load-path
(setq calligrus-exe "calligrus")   ; a string, or a list: '("python" "stub.py")
#+end_src

Doom (=packages.el= not needed; put this in =config.el=):

#+begin_src emacs-lisp
(add-to-list 'load-path "D:/path/to/calligrus/editors/emacs")
(autoload 'calligrus-toggle "calligrus" nil t)
(autoload 'calligrus-stop "calligrus" nil t)
(autoload 'calligrus-open-file "calligrus" nil t)
(after! calligrus
  (setq calligrus-exe "D:/path/to/calligrus.exe"))   ; if it is not on PATH
(map! :after markdown-mode
      :map markdown-mode-map
      :localleader
      "p" #'calligrus-toggle
      "P" #'calligrus-stop
      "o" #'calligrus-open-file)
;; or a global leader key:
(map! :leader :desc "calligrus preview" "t m" #'calligrus-toggle)
#+end_src

Plain Emacs, optionally start the preview for every Markdown buffer:

#+begin_src emacs-lisp
(with-eval-after-load 'markdown-mode
  (define-key markdown-mode-map (kbd "C-c C-v") #'calligrus-toggle))
;; auto-start: (add-hook 'markdown-mode-hook #'calligrus-preview-mode)
#+end_src

* Use

- =M-x calligrus-toggle=: preview the current buffer on/off (starts Calligrus if needed). =C-u= forces it for a buffer whose major mode is not in =calligrus-modes=.
- =follow= (=calligrus-follow=, default on): once the preview is running, every Markdown buffer you visit joins in. Toggling a buffer off mutes it until you toggle it on again.
- =M-x calligrus-stop=: quit Calligrus; all previews off. Quitting Emacs does it too.
- =M-x calligrus-open-file=: open the buffer's file in a separate, unlinked calligrus.
- =calligrus-preview-mode= is the buffer-local minor mode (" MdV" in the mode line).
- If Calligrus exits or crashes: previews turn off and Emacs says so; toggle again to restart. Calligrus's stderr goes to the =*calligrus-log*= buffer.

* Ctrl+click in the preview

Ctrl+click on text in the Calligrus window and Emacs jumps there: Calligrus writes ={"type":"goto","doc":...,"line":N}= on its stdout, and calligrus.el selects the window that shows the buffer (in the selected frame; else one on another visible frame; else the buffer is shown in the selected window), moves point to line N (clamped to the buffer) at its indentation and unfolds what hides it (=outline-show-entry= in outline buffers, =org-reveal= in Org, =reveal-mode=). The usual =cursor= message follows. Emacs then comes back to the front with the keyboard focus (=(setq calligrus-goto-focus nil)= leaves the focus on the preview). =(setq calligrus-goto nil)= ignores the clicks. Unknown or malformed lines on stdout are ignored.

* What is sent

| Emacs event                                     | message                                                                                           |
|-------------------------------------------------+---------------------------------------------------------------------------------------------------|
| preview on, or you switch to a previewed buffer | =open= (+ =cursor=, =search=)                                                                     |
| edits (=after-change-functions=)                | =text=, at most every =calligrus-throttle= (0.15 s) while typing; the last edit is always sent    |
| any command (=post-command-hook=)               | =cursor= line, debounced =calligrus-cursor-delay= (0.05 s), only if the line changed              |
| isearch typing / end                            | =search= (plain text only; regexp isearch sends "")                                               |
| Evil =/ ? * # n N=, =:noh=                      | =search= (advice on =evil-ex-search=, =evil-ex-nohighlight=)                                      |
| =kill-buffer= of a previewed buffer             | =close=                                                                                           |
| =kill-emacs=, =calligrus-stop=                  | =quit=, then stdin is closed                                                                      |

Search: patterns that are regexps cannot be shown faithfully, so they send =""=. Evil's =\<word\>= (from =*=/=#=) and text that went through =regexp-quote= are turned into plain text. Case: isearch uses its own case folding; Evil uses the pattern's. After isearch ends the highlight is cleared (=calligrus-keep-isearch-highlight=: nil / t / =auto= = keep when Evil's isearch module is in use, so =/foo= then =n= behaves like Vim's hlsearch).

* Customize

=calligrus-exe=, =calligrus-throttle=, =calligrus-cursor-delay=, =calligrus-follow=, =calligrus-modes= (default =markdown-mode gfm-mode markdown-ts-mode org-mode=; Org buffers are sent with ="format":"org"=), =calligrus-keep-isearch-highlight=, =calligrus-goto= (default t), =calligrus-goto-focus= (default t), =calligrus-pipe-buffer-size=.

* Performance note (Windows pipes)

Measured with Emacs 31.1 on Windows, sending a 325 KB JSON line to a python sink (ten sends in a row, whole-process time per send):

| pipe                         | per send                                         |
|------------------------------+--------------------------------------------------|
| Emacs default pipe           | about 900-1200 ms (Emacs frozen), roughly 300 KB/s |
| =w32-pipe-buffer-size= = 1 MB | about 8 ms                                       |

So calligrus.el binds =w32-pipe-buffer-size= to =calligrus-pipe-buffer-size= (4 MB) when it starts the process; with that, a 325 KB buffer costs ~4 ms to serialize and ~4 ms to write, and the 0.15 s throttle is plenty. If a document is bigger than the pipe, a send blocks until Calligrus has read enough, so keep it above your largest file.
